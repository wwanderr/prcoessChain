### 1. 父进程拆分优化（关键优化）⭐⭐⭐⭐⭐

**文件**: `ProcessChainBuilder.java` 第1758-1779行

#### 问题描述

原代码使用嵌套循环为虚拟父节点创建边：

```java
// ❌ 优化前：嵌套循环 O(n²)
for (Map.Entry<String, GraphNode> entry : virtualParentsToAdd.entrySet()) {  // 6926次
    String virtualParentId = entry.getKey();
    GraphNode virtualParent = entry.getValue();
    
    subgraph.addNode(virtualParent);
    
    // 🔴 嵌套循环：对每个虚拟父节点，遍历所有节点找子节点
    for (GraphNode node : subgraph.getAllNodes()) {  // 7274次
        if (node.isVirtual()) {
            continue;
        }
        
        String parentGuid = node.getParentProcessGuid();
        
        if (virtualParentId.equals(parentGuid)) {
            subgraph.addEdge(virtualParentId, node.getNodeId());
        }
    }
}
```

**性能问题**：
- 外层循环：6926次
- 内层循环：7274次
- 总比较次数：**6926 × 7274 = 50,376,424次**
- 实际耗时：**约4秒**

#### 优化方案

使用HashMap索引，提前建立 `parentGuid → 子节点列表` 的映射：

```java
// ✅ 优化后：使用索引 O(n)
// 第1步：建立索引（只遍历一次）
Map<String, List<String>> parentToChildren = new HashMap<>();
for (GraphNode node : subgraph.getAllNodes()) {  // 7274次
    if (node.isVirtual()) {
        continue;
    }
    String parentGuid = node.getParentProcessGuid();
    if (parentGuid != null && !parentGuid.isEmpty()) {
        parentToChildren.computeIfAbsent(parentGuid, k -> new ArrayList<>())
            .add(node.getNodeId());
    }
}

// 第2步：使用索引快速创建边
int edgeCount = 0;
for (Map.Entry<String, GraphNode> entry : virtualParentsToAdd.entrySet()) {  // 6926次
    String virtualParentId = entry.getKey();
    GraphNode virtualParent = entry.getValue();
    
    subgraph.addNode(virtualParent);
    
    // ✅ 直接查找子节点，O(1)
    List<String> children = parentToChildren.get(virtualParentId);
    if (children != null) {
        for (String childId : children) {
            subgraph.addEdge(virtualParentId, childId);
            edgeCount++;
        }
    }
}
```

## 附录：性能分析方法论

### 如何发现性能瓶颈

1. **时间戳分析**
   - 在关键代码点添加时间戳日志
   - 计算每个阶段的耗时
   - 定位最耗时的环节

2. **代码静态分析**
   - 搜索嵌套for循环
   - 计算时间复杂度
   - 估算在大数据量下的耗时

3. **日志分析**
   - 观察日志中的时间间隔
   - 找出长时间停顿的地方
   - 分析日志量是否过大

### 优化策略

1. **建立索引**
   - 适用于频繁查找的场景
   - 用空间换时间
   - HashMap/HashSet是最常用的工具

2. **避免重复计算**
   - 缓存计算结果
   - 批量操作替代单个操作
   - 延迟计算（只在需要时计算）

3. **算法优化**
   - 选择合适的数据结构
   - 降低时间复杂度
   - 避免不必要的操作
